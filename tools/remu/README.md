# remu

A function-level emulator for memory images exported from IDA. Given an image
(format 1, written by `rekit/_emu.py`) and a request such as "call the function
at this address with these arguments", it interprets the code in Unicorn and
returns one compact JSON object: why it stopped, the return value, what changed
in the buffers it was given, which imports were called with what, and which
other memory was written (with the strings found there).

It answers questions like "what does this decryption routine produce for this
input" or "what string does this function build" without running the sample.
The code under analysis is interpreted; it never runs natively.

**What it is not.** It is not a sandbox for whole programs. There is no loader,
no process start-up, no DLLs behind the imports, no threads, no exception
dispatch and no real OS. Static initialisers never ran, so global state that
the program sets up at start-up (memory managers, tables, singletons) is
whatever the image holds, usually zero. remu is for leaf-ish routines and
small call trees; when a run strays into uninitialised machinery, the reply
says where and you replace or stub that piece. Tables the program builds
itself (an S-box generated by a loop, a decoded constant table) can be built
first with `init`, which runs the set-up functions in the same machine.

## Running it

    remu call --image <image dir>            # request JSON on stdin, one JSON reply on stdout
    remu call --image <dir> --request f.json
    remu info --image <dir> [--json]         # arch, segments, import counts, emulation layout
    remu stubs [--json]                      # the modelled imports

`remu` is a `/bin/sh` script that starts `.venv/bin/python -I src/remu_main.py`
by path. It looks nothing up on PATH, so it works from IDA's worker process.
Diagnostics (timing, tracebacks of internal errors) go to stderr. The exit code
is 0 whenever a JSON reply was written, including `{"error", "hint"}` replies.

Set-up (once, from this directory): `~/.local/bin/uv sync`. Tests: `uv run pytest`.

Start-up for a trivial request is about 40 ms on the test images and 45-55 ms
on the 13.8 MB Delphi sample (measured with `/usr/bin/time`, warm file cache).
Interpretation runs at roughly 4-5 million instructions per second (a Python
hook sees every instruction), so the default cap of 2 million instructions takes
about half a second.

## Request

A request is a JSON object. Unknown keys are rejected with the list of valid
ones. Addresses and numbers may be ints or strings (`"0x401000"`, `"-1"`).

| key | meaning |
|---|---|
| `func` | address of a function to call; the run ends when it returns to the sentinel return address (`returned`) |
| `start`, `until` | instead of `func`: run a fragment from `start` until it reaches any address in `until` (a list or one address). The start instruction itself never counts as reaching `until`, so `until: [start]` runs one loop iteration |
| `cc` | calling convention for `args`; default `cdecl` (x86), `ms64` (x64 PE), `sysv` (other x64), `aapcs64` (arm64) |
| `args` | argument values (see below) |
| `regs` | extra register presets, `{"esi": value, ...}`; applied after `args` |
| `mem` | memory set-up: a list of buffer specs, each with a `name` for refs and optionally an `addr` |
| `imports` | per-import overrides, keyed by import name or address (slot, thunk or extern address) |
| `replace` | functions in the image to replace by a stub or a fixed result, keyed by address |
| `ret` | how to show the return value: `int` (default), `cstr`, `wstr`, `dstr`, `dastr`, `bytes:N` |
| `ret_reg` | return register if not EAX/RAX/X0 |
| `regs_out` | registers to report after the run, e.g. `["edx"]` |
| `read` | memory to read back after the run (see below) |
| `init` | calls to make first, in order, in the same machine (see below) |
| `dump` | a directory: after the run, write the memory it can have changed there (see below) |
| `max_insns` | instruction cap, default 2 000 000 |
| `timeout` | wall-clock seconds, default 20 (covers the init calls too) |
| `max_chars` | reply budget, default 6000 |
| `on_unknown_import` | `log` (default: log it, return 0) or `stop` |
| `map_on_demand` | `false` (default), `true` (up to 256 zero pages) or a page count: map zero pages where the code reads or writes unmapped memory. Never for the first 64 KB (NULL derefs still stop) and never for fetches |
| `trace` | `true` or a cap: record function entries reached by a call (default cap 200) |
| `acp` | ANSI code page for CP_ACP conversions and AnsiStrings, default 1252 (use 936 for GBK) |
| `heap_size`, `stack_size` | default 64 MB and 1 MB |
| `fields` | keep only these reply keys (plus `id` and `stop`); for sweeps |
| `id` | echoed back |

### Argument and memory values

A value is one of:

| spec | becomes |
|---|---|
| `5`, `"0x401000"`, `"-1"`, `{"int": 5}` | that integer |
| `{"ref": "name+0x10"}` | address of a named block (or builtin) plus offset; `-` works too |
| `{"bytes": "de ad be ef", "size": N}` | a buffer holding these bytes, zero-padded to `size` |
| `{"str": "text", "enc": "utf-8", "size": N}` | a NUL-terminated byte string (`enc` is any Python codec, e.g. `gbk`) |
| `{"wstr": "text", "size": N}` | a NUL-terminated UTF-16LE string |
| `{"out": N, "fill": "cc"}` | an N-byte output buffer (zeros unless `fill`) |
| `{"dstr": "text"}` | a Delphi UnicodeString: pointer to the chars, with codepage 1200, elemsize 2, refcount -1 (a constant, so the RTL never frees it) and length in front (12-byte header; 16 on 64-bit) |
| `{"dastr": "text", "cp": 1252}` | a Delphi AnsiString, same layout with 1-byte chars |
| `{"struct": [fields]}` | a laid-out structure, see below |

Buffer specs (everything but ints and refs) are allocated in the **args**
region and passed by pointer. Each may carry `"name"` (otherwise top-level
arguments are named `a1`, `a2`, ... like IDA's, and `mem` entries `mem0`, ...)
and `"addr"` to place it at a chosen address. Any mapped address is allowed;
the **scratch** region (`0x20000000`-`0x21000000` unless the image is there;
`remu info` shows the layout) is reserved for the caller. Refs may point
forwards or backwards. Builtin ref names: `scratch`, `args_region`, `heap`,
`stack_top`, `image`, `sentinel`, and for PE images `teb` and `peb`.

Struct fields, laid out in order with no implicit padding:
`{"u8"|"u16"|"u32"|"u64"|"i8"|"i16"|"i32"|"i64": value}`, `{"ptr": value}`
(pointer-sized), `{"f32": x}`, `{"f64": x}`, inline data `{"bytes": hex}`,
`{"str": s}`, `{"wstr": s}`, padding `{"zero": n}` and `{"align": n}`; a bare
integer is a pointer-sized field. A field's value may itself be a buffer spec,
which is allocated separately and its pointer stored.

Nested example (a pointer to a struct whose field +4 points into a
length-prefixed array):

```json
{"func": "0x495bd0", "cc": "delphi",
 "mem": [{"name": "arr", "struct": [{"u32": 3}, {"u32": 5}, {"u32": 0}, {"u32": 0}]}],
 "args": [{"struct": [{"u32": 0}, {"ptr": {"ref": "arr+4"}}]}]}
```

### Calling conventions and explicit locations

| `cc` | arch | integer arguments |
|---|---|---|
| `cdecl` | x86 | all on the stack, caller cleans |
| `stdcall` | x86 | all on the stack, callee pops |
| `fastcall` | x86 | ECX, EDX, rest on the stack (Microsoft) |
| `thiscall` | x86 | ECX, rest on the stack |
| `delphi` (alias `register`, `borland`) | x86 | EAX, EDX, ECX, rest pushed **left to right** (so the last argument is nearest the return address), callee pops |
| `ms64` | x64 | RCX, RDX, R8, R9, then the stack above 32 bytes of home space |
| `sysv` | x64 | RDI, RSI, RDX, RCX, R8, R9, then the stack |
| `aapcs64` | arm64 | X0-X7, then 8-byte stack slots |
| `usercall` | any | no default slots: every argument needs `reg` or `stack` |

Any argument may name its location instead: `{"int": 7, "reg": "esi"}`,
`{"str": "x", "stack": 8}`. `stack: N` is the byte offset from the first slot
above the return address (`[esp+4+N]` on x86, `[rsp+8+N]` on x64 where the
ms64 home space is `N = 0..0x18`, `[sp+N]` on arm64). Arguments without a
location take the convention's slots in order. Only integer/pointer arguments
are modelled; pass a 64-bit integer on x86 as two arguments, and preset
floating-point registers through `regs` (`xmm0`, `q0` take integers).

**Delphi.** IDA writes the register convention as, for example,
`int __usercall f@<eax>(int a1@<eax>, int a2@<edx>, int a3@<ecx>)`; use
`"cc": "delphi"` (or `usercall` with explicit registers). With IDA's compiler
set to Delphi, a prototype shown as `__fastcall` also means this Borland
convention, not Microsoft's ECX/EDX; remu warns when `fastcall` is used on an
image that looks like Delphi (it has `.itext`/`.didata` segments). Functions
returning a string take a hidden last argument, the address of the result
variable: pass `{"out": 4, "name": "res"}` and read it back with
`{"addr": {"ref": "res"}, "deref": 1, "as": "dstr"}`. Delphi's memory manager
is set up by start-up code that never ran, so anything that allocates
(`System.@GetMem`) faults inside it; replace GetMem with the heap stub, e.g.
`"replace": {"0x407164": {"stub": "malloc", "cc": "delphi"}}` (0x407164 is
GetMem in the sample; find it in other binaries as the function every
`NewUnicodeString` calls).

### Init calls

Programs often fill tables at start-up or on first use (an S-box built by a
loop, constants decoded from a masked table, a CRC table). A function that
reads such a table computes garbage when called alone, because the image holds
zeros there. `init` is a list of calls made before the request's own call, in
the same machine:

```json
{"func": "0x1002660", "args": [{"ref": "seed"}, {"out": 16}],
 "init": ["0x1002480", "0x1002890",
          {"func": "0x1002a00", "args": [3, {"out": 8, "name": "seed"}]}]}
```

- An entry is an address (called with no arguments and the default calling
  convention) or an object with `func` and optionally `args`, `cc`, `regs`,
  `mem`, `replace`, `imports` and `max_insns` (default 2 000 000 per entry).
  Other keys are refused: `timeout`, `heap_size`, `acp`, `map_on_demand` and
  `on_unknown_import` come from the request, init results are read back with
  the request's `read`, and fragments (`start`/`until`) are for the main call
  only.
- Memory persists from one call to the next: image data, the heap, named
  buffers, and the modelled state (last error, TLS, tick counter). Each call
  gets fresh general registers and a zeroed stack.
- Buffers named in an entry can be referenced by later entries and the main
  call (`{"ref": "seed"}`), so one step's output is the next step's input.
  Unnamed buffers of entry `i` are called `initI.a1`, `initI.mem0`, ...;
  an explicit name may be used only once per request.
- The request's `replace` and `imports` apply to init calls too; an entry's
  own `replace`/`imports` are merged over them for that entry.
- The reply describes the main call only: `buffers`, `writes`, `imports`,
  `insns` and `stack_strings` start from the state init left behind, and init
  buffers the main call did not change are not listed. `init` in the reply
  gives one `{"func", "stop", "ret", "insns"}` per entry.
- If an entry does not return, the main call does not run and the reply's
  stop is `{"reason": "init_failed", "at", "entry", "func", "cause",
  "detail"}`, where `cause` is that entry's own stop (reason, address,
  faulting instruction...); `regs`, `imports` and `trace` then describe the
  failed entry, so an allocator it stalled in can be found and replaced.
- In a batch every request runs its own `init` from the pristine image;
  `init` in `defaults` is repeated for each request.

### Dumping memory after the run

`"dump": "/some/dir"` writes, after the main call (or after the init entry
that failed), the memory the run can have changed, so a caller can scan the
state that start-up code left behind (tables decoded or generated at run time):

- every image segment whose bytes now differ from the image, whole;
- the used part of the heap, with its blocks (`addr`, `size`, allocating `from`);
- the used part of the args region, with the named buffers in it;
- named blocks placed outside the image and the args region (`addr` in scratch).

Each region is one raw file `r<N>.bin`; `dump.json` lists them as
`{"kind": "segment"|"heap"|"args"|"buffer", "name", "start", "size", "file",
"changed": [[start, end], ...]}` (changed byte ranges against the image, or
against zero for remu's own regions; `blocks`/`buffers` where they apply),
plus `init` and `func`. The directory is created if needed and existing files
in it are overwritten. The reply gets `"dump": {"dir", "regions", "bytes",
"changed"}`. The stack and the TEB/PEB block are not dumped.

### Imports

Execution that reaches an import is intercepted: an IAT slot (remu writes a
stub address into every import slot), a thunk from the image's `thunks` table
(intercepted at the thunk's first instruction), an extern symbol address, or a
pointer returned by the modelled `GetProcAddress`. A stub reads its arguments
with the platform convention (stack on x86, the default `cc` elsewhere), sets
the return register and returns to the caller, popping `purge` bytes on x86.

The clean-up on x86 comes from, in order: the request override, the image's
`purge` (IDA prototype), the stub's own table (Windows API stubs are stdcall,
C runtime stubs cdecl), `4 * nargs` from the override, else 0 with a warning
that names the import (a wrong guess shows up as a corrupted stack later).

Imports without a stub are logged with their arguments (`nargs` from the
image, else the first four slots, marked) and return 0, unless
`on_unknown_import` is `stop`. Overrides:

```json
"imports": {
  "GetTickCount": {"ret": 1000},
  "GetComputerNameW": {"ret": 1, "write": [{"arg": 0, "wstr": "DESKTOP-1"}, {"arg": 1, "u32": 9}]},
  "GetCommandLineW": {"ret": {"wstr": "app.exe /x"}},
  "SomeStdcallFn": {"nargs": 3},
  "0xf23930": {"stub": "lstrcpyW"},
  "CreateFileW": {"stop": true}
}
```

`ret` is any value spec (buffers are allocated once per run); `write` items
are `{"arg": i, "off": n, <struct field>}` and write through pointer argument
`i` (0-based); `stub` borrows another stub's model; `stop` ends the run there
(`import_stop`). `replace` takes the same keys plus `cc` (how the stub reads
its arguments and, on x86, whether the callee pops) and `name`, and applies to
any address in the image.

### Reading memory back

`read` items: `{"addr": value}` (a value spec, usually a ref or an address),
`{"reg": "eax"}` (the register's final value) or `{"ret": true}`; then
`"deref": n` (follow n pointers), `"off": n` (added after dereferencing),
`"size": n`, `"as"`: `hex` (default, 64 bytes), `cstr`, `wstr`, `dstr`,
`dastr`, `u8 u16 u32 u64 i32 i64 ptr`; optional `"name"`.

### Batches

stdin may hold a list of requests, or
`{"requests": [...], "defaults": {...}, "max_chars": N}` where each request is
merged over `defaults`. Every request starts from a clean machine (its `init`
calls, if any, run again) (a new
Unicorn instance with the image freshly written; about 4-5 ms each for the
13.8 MB sample). The reply is
`{"total": N, "reasons": {"returned": N, ...}, "results": [...]}`; each result
gets `max_chars / N` of the budget (at least 150), and if the results still do
not fit, the tail is dropped and `more` says how many are shown.

## Reply

```json
{"id": ..., "stop": {"reason": "returned", "at": "0x495c08"}, "insns": 59,
 "ret": "0x1", "ret_signed": -1, "popped": 0, "ret_points_to": {...}, "ret_view": {...},
 "regs": {...}, "regs_out": {...},
 "init": [{"func": "0x1002480", "stop": "returned", "ret": "0x0", "insns": 4113}],
 "buffers": {"total": N, "top": [...]}, "unchanged": {"total": N, "top": ["a1", ...]},
 "reads": [...], "imports": {"total": N, "top": [...], "counts": {...}},
 "writes": {"total": N, "bytes": B, "top": [...]}, "stack_strings": {"total": N, "top": [...]},
 "trace": {"total": N, "top": [...]}, "mapped_on_demand": {...},
 "warnings": {"total": N, "top": [...]}, "ms": 5, "truncated": "..."}
```

- `stop.reason`: `returned`, `until`, `max_insns`, `timeout`, `unmapped_read`,
  `unmapped_write`, `unmapped_fetch`, `invalid_insn`, `interrupt` (int3, int
  0x2d, divide error, brk...; with `intno` and `name`), `syscall` (syscall,
  sysenter, int 0x2e/0x80, svc), `halt` (hlt), `unknown_import`,
  `import_stop`, `exception`, `exit`, `cpu_exception`, `error`, `init_failed`
  (an init entry did not return; see Init calls), and `stopped`
  if the emulator ended for a reason remu could not name. `at` is where it stopped: the last instruction (`ret`) for
  `returned`, the faulting instruction for data faults (with `addr`, `size`,
  `insn` and the segment-relative `in`), the target for `unmapped_fetch` (with
  `from`), the import's stub or thunk for import stops (with `fn` and
  `ret_to`). Every reason other than `returned` comes with `regs`.
- `insns`: instructions executed (an import call counts as one), by the main
  call alone; `init` lists each init call's count.
- `ret` only for `returned`; `ret_signed` when the top bit is set; `popped`
  (x86 calls) is how many argument bytes the callee removed, which tells
  cdecl from stdcall; `ret_points_to` appears when the return value points at
  something that reads as a string.
- `buffers`: every argument/`mem` buffer whose bytes changed, with the changed
  offset range, `hex` and readable views (`text` one char per byte, `cstr`,
  `wstr`, Delphi views, `points_to` for pointer-sized buffers). Buffers over
  256 bytes show a 256-byte window starting at the first change, and `shown`
  says which. Unchanged buffers are listed by name.
- `imports`: calls in order as `{"fn": "module!name", "from": return address,
  "args": [...], "ret", "model": "stub"|"override"|"none, returned 0"}`;
  string arguments are shown inline (`"0x21000000 \"HELLO\""`, `L"..."` for
  UTF-16). Identical consecutive calls fold into one entry with `n`; `counts`
  sums per function. At most 400 entries are kept.
- `writes`: memory written during the run outside the argument buffers, the
  stack and the TEB/TLS block, coalesced (gaps up to 16 bytes merged), largest
  first, at most 50; each with where it is (`.data+0x100`, `heap block ...
  from HeapAlloc`), the first 64 bytes, and the ASCII/UTF-16 strings in it
  (first 64 KB scanned). Stub writes (memcpy, MultiByteToWideChar...) count.
- `stack_strings`: strings left on the stack (where local buffers live).
- `trace`: call targets in order, `to`/`from` (the call instruction) and `n`
  for repeats from the same site.

**Budget.** The serialised reply stays within `max_chars`. Sections give up
space in this order: trace, stack strings, on-demand pages, writes, unchanged,
warnings, imports, reads, buffers, regs, return views; inside a section long
strings are halved first (down to 120 chars), then list tails go, then
everything shrinks to empty lists. Cut strings end in `...[+N chars]`, lists
that show fewer than their `total` carry `more` ("3 of 17 shown"), and
`truncated` names the sections that were shortened. Nothing is dropped without
one of those markers.

**Errors.** A request that cannot run gives `{"error": ..., "hint": ...}`
(with `id` if one was given); in a batch, per result.

## Memory layout and environment

Image segments are mapped page-aligned (neighbouring segments sharing a page
are merged) and all read/write/execute; segment permissions are not enforced.
`file` bytes are written from each segment start, the rest is zero. remu adds
these regions, moving any of them up in 16 MB steps if the image is in the way
(`remu info` prints the actual layout; a warning says when scratch moved):

| region | default | contents |
|---|---|---|
| scratch | 0x20000000, 16 MB | yours: `mem` blocks with `addr` |
| args | 0x21000000, 16 MB | auto-allocated argument buffers |
| heap | 0x30000000, 64 MB | malloc/HeapAlloc/VirtualAlloc/... (bump allocator, zeroed, never reused, 16-byte gaps) |
| stack | 0x7E000000, 1 MB | SP starts 4 KB below the top; frame pointer preset near the top |
| stubs | 0x7FC00000 | the return sentinel (first slot) and one 16-byte slot per import, filled with int3/brk |
| env | 0x7FD00000, 128 KB | TEB, PEB, loader data, TLS array and block, GDT |
| kuser | 0x7FFE0000 (PE) | a zeroed KUSER_SHARED_DATA page |

For PE images a minimal TEB/PEB is reachable through FS (x86, via a GDT
descriptor) or GS (x64) or X18 (arm64): `fs:[0]` is the end of the SEH chain
(0xFFFFFFFF), stack base/limit, `Self`, fake process/thread ids,
`ThreadLocalStoragePointer` (64 slots, all pointing at one zeroed 64 KB block,
so Delphi threadvars read zeros), PEB with `BeingDebugged = 0`,
`ImageBaseAddress`, `ProcessHeap`, `NumberOfProcessors = 4`, OS 10.0.19045,
and a loader block whose module lists are empty (walking them ends at once).
For ELF/Mach-O the FS/GS base (x64), GS (x86) or TPIDR_EL0/TPIDRRO_EL0 (arm64)
points at a zeroed TLS block whose first word points to itself.

CPUID is answered by remu: a GenuineIntel CPU with SSE up to SSE4.2, POPCNT
and AES-NI, and no AVX/XSAVE, so code that dispatches on CPUID takes paths the
emulator can execute (the x86 CPU model is Skylake so SSSE3/SSE4/AES-NI
decode; AVX2 does not). arm64 uses Unicorn's `max` CPU model (LSE atomics etc.).

## Example (real sample)

`sample.bin` is a 32-bit Delphi PE. `sub_495BD0` counts records whose
first dword is not -1 and not equal to `(n - 1) & index`:

```sh
remu call --image .../sample.bin.4cc1bd35fc1e <<'EOF'
{"func": "0x495bd0", "cc": "delphi",
 "mem": [{"name": "arr", "struct": [{"u32": 4},
          {"u32": 5}, {"u32": 0}, {"u32": 0},
          {"u32": "0xffffffff"}, {"u32": 0}, {"u32": 0},
          {"u32": 2}, {"u32": 0}, {"u32": 0},
          {"u32": 7}, {"u32": 0}, {"u32": 0}]}],
 "args": [{"name": "obj", "struct": [{"u32": 0}, {"ptr": {"ref": "arr+4"}}]}]}
EOF
```

```json
{"stop":{"reason":"returned","at":"0x495c08"},"insns":59,"ret":"0x1","popped":0,
 "unchanged":{"total":2,"top":["arr","obj"]},"ms":5}
```

`SysUtils.AnsiUpperCase` (0x434b9c) copies its argument through the RTL and
calls `CharUpperBuffW` through an import thunk; with GetMem replaced:

```json
{"func": "0x434b9c", "cc": "delphi",
 "replace": {"0x407164": {"stub": "malloc", "cc": "delphi", "name": "System.GetMem"}},
 "args": [{"dstr": "Hello, wörld 世界"}, {"out": 4, "name": "result"}],
 "read": [{"addr": {"ref": "result"}, "deref": 1, "as": "dstr"}]}
```

gives `"reads":[{"addr":"0x3000001c","len":15,"dstr":"HELLO, WÖRLD 世界",...}]`,
the two calls in `imports` (`System.GetMem(0x2c)`, `user32!CharUpperBuffW(
0x3000001c L"Hello, wörld 世界", 0xf)`) and the heap block in `writes`.
Without the replacement the same kind of call stops with
`{"reason":"unmapped_read","at":"0x405b11","addr":"0x10","insn":"mov eax, dword ptr [edx + 0x10]"}`
inside the uninitialised FastMM, and `trace` shows the path
`0x40b2f8 -> 0x407164 (GetMem) -> 0x405ae4`.

## Limits and known gaps

- Function-level only: no process start-up, static constructors, DLL code,
  loader, or real API behaviour beyond the stubs above. Global state is the
  image snapshot (usually zero for anything set at start-up) plus whatever
  the request's `init` calls write; you have to name those set-up functions.
- No exception dispatch: SEH frames can be built and torn down (`fs:[0]`
  works), but a raised exception or a CPU fault ends the run. `try/except`
  around faulting code does not help.
- No threads, waits, callbacks into the code from the "OS", timers or window
  messages.
- Anti-emulation: the timing APIs see a deterministic tick counter, but the
  `rdtsc` instruction returns the emulator's host-derived counter (Unicorn
  2.1.4 cannot hook it), so it is not deterministic; CPUID is fixed; `PEB.BeingDebugged` and `NtGlobalFlag` are 0; KUSER_SHARED_DATA is
  zero; PEB module lists are empty, so API-hashing loaders that walk them find
  nothing and parse no export tables; `GetModuleHandle`/`LoadLibrary` return
  fake handles that fault if dereferenced. Unicorn itself is detectable (e.g.
  by instruction quirks).
- Floating point: x87/SSE/SSE4/AES-NI execute; AVX/AVX2/AVX-512 do not
  (`invalid_insn`). Floating-point arguments and return values are not part
  of the calling-convention support (use `regs`, read `regs_out`).
- Segment permissions are not enforced (everything is RWX), so writes to code
  and execution from data succeed. Self-modifying code within one run relies
  on Unicorn's translation-cache invalidation; one case is tested (patching
  the next instruction). Across requests nothing carries over: each request
  starts from the image bytes again (init calls carry over only within one
  request).
- `VirtualAlloc` ignores a requested address unless it is already mapped
  (warns); heap memory is never reused or poisoned; real heaps return
  uninitialised memory, remu's is always zero.
- 64-bit Delphi string headers (16 bytes) and arm64 Windows (X18 TEB) are
  implemented but untested; Apple arm64's packed stack arguments are not
  modelled (8-byte slots are used); variadic stubs read floats only on x86 and
  Win64.
- Imports without a prototype on x86 are assumed to pop nothing (warned).
- Instruction counts come from a per-instruction hook: an intercepted import
  counts as one, and an instruction the emulator re-translates (after code
  modifies its own block) can be counted twice.
- Strings in replies are found heuristically (ASCII runs of at least 4, UTF-16
  runs filtered against binary noise and pointer-shaped data); short or
  unusual UTF-16 text may be missed and noise may occasionally slip through.
  `read` gives the exact bytes.
- Only formats `x86`/32, `x64`/64 and `arm64`/64 little-endian are accepted;
  anything else is rejected with an error.

## Versions

Python 3.13 (uv-managed, `.python-version`), unicorn 2.1.4 (pinned
`>=2.1.4,<2.2`), capstone 5.0.9 (`>=5.0,<6`, used to name the faulting
instruction), pytest 9 for the tests; see `uv.lock`.
